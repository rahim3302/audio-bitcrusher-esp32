# Working with this user

- Always look for the simplest functional implementation before proposing code.
- Prioritize working, correct behavior. Add complexity only when the simpler version cannot meet the current requirement.
- Use concrete values and straightforward code for the current exercise. Avoid premature generalization, abstraction, dynamic allocation, or future-proofing.
- When more complexity is necessary, explain the specific reason briefly before introducing it, one concept at a time.
- Explain with small numerical examples and plain language. The user knows C but is learning audio DSP and benefits from gradual explanations of pointers and state.
- Keep necessary bounds and correctness checks, but implement and explain them in the simplest way that works for the chosen settings.
- Do not change code merely to prepare for hypothetical future features.
